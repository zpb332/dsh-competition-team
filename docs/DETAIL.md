# 竞赛智队

把一场比赛拆成一支**可自定义**的智能团队：角色分队长、核心、队员三类，在左侧入口的画布上连线定义工作流、给每个角色挑模型，确认后各成员在独立会话里开工，前一位的产出自动交接给下一位。

## 它能做什么

1. **三类角色，随便加**：队长（总指挥）、核心（二级大脑）、队员（执行）。建队先给 1 队长 + 2 核心 + 2 队员的模板，每张卡可改名、改职责、改分类、加人删人；队长全局只允许一个。
2. **画布定义工作流**：拖动卡片摆位置；从卡片底部的圆点拖到另一张卡片（或点一下圆点再点目标卡片）即可连线，表示「等它做完再做我」；点连线可删除。前置关系实时显示在右侧检查器里，成环会被拦下。
3. **每个角色单独挑模型**：右侧「模型」下拉列出当前可用的全部 provider / 模型；不选就用默认模型。开工时会把选择写进该成员的会话。
4. **确认后才工作**：建出来的团队是草稿态，左侧底部显示「待配置」。点「确认并开跑」才锁定工作流并派活；确认后不能再改流程，避免跑到一半换规则。
5. **每个成员一个独立会话**：真实的 DSH 会话，加入现有工作区分组，标题形如 `[APMCM 2025 B] 建模手`，可单独点开继续追问。
6. **自动接力 + 跨会话读取**：下游开工前先读上游的 `handoffs/<角色>.md`；队长或任意会话也能用 `competition_team` 工具的 `read` 动作直接取回某位成员的汇报、交接和产物清单。
7. **左侧栏实时进程**：最左导航入口；底部常驻「智队 3/5 · 建模手进行中」；主面板树状图显示运行中节点、最近一次工具调用、耗时和产物数。
8. **产物直接看**：图片点开是面板内大图，代码 / JSON / Markdown 在面板里读；可重跑某一棒（两次确认）、停止、追加指令；审核判「需返工」时头部有标记。

## 怎么用

- 点左侧「竞赛智队」→「新建竞赛团队」，填队名、题目、共享目录。
- 在画布上改角色、连线、选模型 →「保存草稿」可随时存 →「确认并开跑」。
- 也可以直接对当前会话说「用 APMCM 2025 B 题建个竞赛队，角色我待会儿自己调」：队长会建好草稿并提示你去面板确认。


## 可靠性（这一版新增）

- **接力守卫**：一轮结束若既没有交接文件、也没有真实产物，会先自动追问一次「补交接/补产物」；第二次仍不合格就标为「已阻塞」并写明原因，而不是假装完成。
- **结构化交接**：`handoffs/<角色>.md` 第一行要求一段 `<!-- competition-team {...} -->` 元数据（status / artifacts / verdict / blockers）。插件会解析它、核对 `artifacts` 里的路径是否真的存在；缺失则同样触发守卫。
- **确认前预检**：点「确认并开跑」之前就检查 brief 是否为空、角色是否填了名称和职责、依赖是否成环、所选模型是否在当前可用路由里；不合格直接列出原因，不会跑到一半才炸。
- **审核员只读**：审核类角色默认以只读沙箱运行（`sandbox/mode = read-only`、`approval/policy = never`），不能改文件，也就没法「自己改完自己审」；它的结论由插件代为落盘。编辑器右侧可以按角色开关，旧团队里名字带「审核/review」的角色会在加载时自动迁移为只读。
- **幂等确认**：团队已确认但没跑起来（例如宿主重载打断）时再点一次确认会继续派活；面板上也会出现「开始执行」按钮。


## 队长频道（这一版新增）

- **用户意见直达队长**：团队开工后，面板顶部常驻「队长频道」。可以直接点「打开队长会话」到队长的会话里提意见，也可以在面板里「给队长留言」，文字会作为一条普通用户消息进入队长会话。
- **队长会分析再派活**：队长会话的提示词里带一段协调协议——收到意见先 `competition_team action=status` 看全局、`action=read` 读相关成员结果，再用 `action=dispatch` 给成员派/改任务、`action=message` 追加指令、`action=revise` 返工，最后回报改了什么。队长不会替成员写产物。
- **意见与回应留痕**：用户发给队长的意见、队长最近一次回应都会记在团队里，面板的队长频道实时显示；刷新、重启都还在。系统注入的时间/上下文消息会被过滤，不会混进意见列表。
- **过程透明**：每个成员节点都有「最近动态」——最近几次工具调用和阶段汇报带时间戳，跑完也保留，不会一完成就把过程抹掉。
- **派活语义**：`dispatch` 会更新成员的任务描述并重新开工（依赖没完成会被拒绝）；`message` 只追加一句指令，同样尊重依赖顺序。


## 审计、意见合并与停滞（这一版新增）

- **队长操作记录**：`dispatch / message / start / stop / revise / feedback` 都会落一条审计（谁、对谁、做了什么、摘要），面板的队长频道显示最近三条。回复文本和实际动作分开记，队长嘴上说的不算数。
- **意见合并**：用户意见先排队 10 秒，攒成一条再交给队长；队长忙着的时候继续排队，等它这一轮结束再合并发送。面板显示「排队 N 条」，合并后的提示带 `【用户意见】` 标记，不会被再次记成新意见。
- **停滞检测**：插件每 60 秒巡检一次——成员处于 `running` 且超过 8 分钟没有任何事件（`COMPETITION_STALL_MS` 可覆盖），标为「可能停滞」并记一条审计；下一条事件到达时自动恢复为 `running`。宿主重载后没有活 Agent 的成员由 `reconcile` 标成失败并提示重试。
- **工具收口**：`feedback` 只保留给面板/用户侧 HTTP 入口，成员工具面不再暴露——测试里出现过队员把「给队长的汇报」当 feedback 发出去，造成串话。


## 提案制（这一版新增）

- **成员不能直接改团队**：队长对成员发起的 `dispatch / message / revise / start / stop` 不再立即执行，而是写成一条提案（`pending`），等用户在面板批准；`create / configure / confirm / delete / setAuto` 对成员直接拒绝。
- **提案对象**：`{id, type, from, target, task, note, reason, status, createdAt}`，状态 `pending → approved / rejected / expired / failed`；30 分钟内有效，过期不可批。
- **面板审批**：队长频道下方出现提案卡片（类型、谁→谁、新任务、说明、理由），「批准」立即执行，「驳回」只记录。批准后审计里能看到 `propose → dispatch → approve` 三段，谁提的、谁批的、执行结果都可查。
- **口头与动作分离**：队长回复里说「已派活」不算数，面板只认提案和审计；提案未批准时成员状态不会变化。


## 提案回灌与通知（这一版新增）

- **回灌队长**：提案被批准/驳回后，插件往队长会话发一条 `【提案结果】`（类型 → 目标：结果 + 「不要重复提交」）。队长据此收尾，不会一直以为还在 pending。这条消息不会混进用户意见列表。
- **浏览器通知**：面板里可点「开启通知」申请权限；之后出现新的待批准提案、成员阻塞、成员停滞时发系统通知，点击通知回到面板。已通知过的提案记在本地，刷新不会重复轰炸。
- **待批准角标**：左栏底部状态行显示「待批准 N」，频道条上也有同名角标；批准/驳回后自动消失。
- **成本提醒**：每次批准/驳回都会让队长跑一轮（回灌），这是有 token 成本的；介意的话后续可改成静默记录。


## 批准前冲突检查（这一版新增）

- 提案创建时会记一份 `base` 快照：目标任务、状态、依赖、依赖是否完成、当时的团队判定。
- 批准时逐项比对，命中就判 `stale`、不执行，并告诉用户和队长原因：
  - `target-missing` 目标角色没了；
  - `task-changed` 目标任务在提案后被改过；
  - `deps-changed` 依赖完成情况变了；
  - `not-pending` / `member-idle` 开工/停止类提案的目标状态已经不对；
  - `verdict-changed` 返工类提案的团队判定已变。
- 判过期后：提案状态 `stale`、审计记 `系统 · stale`、队长收到「已过期（状态已变化，未执行）」的回灌；面板会提示具体冲突字段。
- 过期提案不会执行，也不会留在待批列表里。


## 测试（这一版新增）

- `npm test` 跑 `node --test`，15 个用例全绿；用模拟宿主（内存 Session + 临时 DSH_HOME/工作目录）直接驱动 `TeamStore`，不需要启动 DSH。
- 覆盖：交接块解析（结构化/自然语言/损坏）、DAG 校验、确认前预检、接力守卫（追一次→阻塞）、结构化交接验收、只读审核员的权限事件与裁决、提案批准、提案过期、批准前冲突（task-changed）、意见合并、停滞标记与事件恢复。
- 未覆盖：HTTP 路由、浏览器端渲染、真实模型/会话日志。这些仍靠手动验收。
- 目录：`test/*.test.mjs` + `test-support/helpers.mjs`。


## 预算与成本（这一版新增）

- **token 累计**：每次 `assistant/message` 带 `usage` 时，把 `totalTokens`（缺省用 input+output）记进当前回合；回合结束落盘到成员。面板成员详情显示 token，团队总量在频道条上。
- **团队预算**：新队默认 3,000,000 token；点频道条的「预算」可改，留空 = 不限。80% 记一次警告审计，100% 标为用尽。
- **用尽即暂停**：`start / dispatch / message / feedback / startReady / revise` 在预算用尽时一律返回 `budget-exhausted`；已批准的提案执行也会失败并标 `failed`。把预算调高后立即恢复。
- **状态可见**：频道条 `预算 436k / 3.00M`、footer 的「预算 82% / 预算用尽」、满额时频道下方的红条。
- **口径说明**：token 数来自 provider 的 usage（可能含缓存读入），不是本地估算；预算在回合边界检查，单轮可能略微超出上限。


## 停滞自救与跳过（这一版新增）

- **自动重试一次**：watchdog 发现成员 `running` 且超过 8 分钟无事件，会取消当前轮、标回 `pending`，再带 `【停滞恢复】` 的提示重发；`stallRetries` 记一次。
- **第二次仍无响应**：标 `failed`（error=`stalled`），不再自动重试；审计记「停滞未恢复」。
- **预算优先**：团队预算用尽时，第一次也不自动重试，直接失败，避免越卡越烧。
- **跳过**：对 `stalled / failed / blocked` 可以 `skip`，成员变 `skipped`；下游依赖把 `skipped` 当作已完成，prompt 里明确写「已跳过，没有交接」，不会假装有产物。
- **面板**：`stalled / failed / skipped` 行的主按钮变成「继续」，并出现「跳过」；确认后自动接力下游。
- **边界**：取消会丢弃该轮未完成的部分（已落盘产物保留）；自动重试计入预算；宿主重载中断的成员仍是 `failed` + 手动「继续」，没有自动续跑。


## 提案历史与批准前编辑（这一版新增）

- **批准前编辑**：待批提案可以直接改 `task / note`，保存后审计记 `edit`，批准时按改后的内容执行；提案卡片显示「已修改」。
- **已处理列表**：频道下方可折叠「已处理 · N」，列出 `approved / rejected / stale / expired / failed` 的提案：时间、状态、类型、谁 → 谁、任务/说明摘要。
- **过期可见**：超过 30 分钟的待批提案在历史里标「已过期」，不再直接消失。
- **边界**：历史只保留最近 10 条（快照上限），更早的要去 `team.json` / 审计里找；编辑只允许 `pending`，已决或过期都会拒绝；没有 diff 视图。


## 中断续跑与启动自愈（这一版新增）

- **中断标记**：插件加载时 `reconcile` 发现成员在跑但没有活 Agent，标 `failed` + `error=interrupted`（面板显示「宿主重启中断」），不再是笼统的失败。
- **自动续跑一次**：启动时对 `interrupted` 成员，预算没超、依赖满足、`resumeAttempts < 1` → 标回 `pending`，带 `【中断恢复】` 的提示重开，`resumeAttempts + 1`；续跑失败或再次中断就停在 `failed`，不再自动烧。
- **启动自愈**：已确认、`auto` 未关、**且曾经启动过**（`startedOnce`）、没有运行成员、但有 ready 待办的队伍，启动时自动 `startReady`——修掉「确认了但没跑起来」的僵局；从没启动过的队不会被自愈拉起来。
- **边界**：草稿队不动；`auto=false` 的队不自动接力（但中断的成员仍会续跑一次）；续跑计入预算；只续一次。


## 组织模型：队长是所有成员的直属上级（这一版调整）

- **扁平汇报**：默认所有非队长成员的 `deps` 都包含 `captain`；数据依赖再叠加。队长不需要层层转达，读题后直接给每个人下任务。
- **任务书**：队长在 `artifacts/captain/plan.md` 里为每位成员写一段（目标、输入、产出、依赖、验收口径）；成员开工前先读自己那一段，和固定任务冲突时以任务书为准并说明。
- **依赖照旧**：队长是「谁给你派活」，依赖是「你等谁的数据」。比如核心 B 仍要等核心 A 的模型，论文手等核心 B，审核员等论文手——只是这些等待不再等于汇报关系。
- **面板**：成员详情显示「直属上级：队长」。


## 队长任务书提案（这一版新增）

- 队长在 `artifacts/captain/plan.md` 里写一段机器可读的分配：
  `<!-- competition-team-assignments [{"role":"core-a","task":"..."}] -->`。
- 队长任务轮结束时（或在队长频道里改了计划后），插件解析它，只保留与现有任务不同的成员，生成**一条** `assignments` 提案；任务书待批期间 `startReady` 暂停，成员不会带着旧任务先跑。
- 批准：整队 `member.task` 一次性更新（`taskSource=captain`），审计记 `assign`，然后按 auto 继续；驳回：保留旧任务，恢复接力。
- 同一时刻只保留一条待批任务书，重复提交会覆盖；任务书提案不支持逐条编辑，要改单人用 `dispatch` 提案。


## 任务书校验与可见性（这一版新增）

- **解析告警**：`malformed-json`、`not-array`、`bad-entry`、`task-too-short:<role>`、`unknown-role:<role>`、`no-block`（plan.md 存在但没有机器块）都会记进 `assignmentCheck`，面板显示「任务书有 N 处问题」。
- **部分生效**：有合法条目时仍提交对应成员，非法条目跳过并在告警里点名；没有变化就不提案。
- **plan.md 预览**：频道条上的「任务书」按钮直接打开 `artifacts/captain/plan.md`，批准前能看原文。
- **下一轮生效**：任务书批准时如果成员正在跑，标 `taskPending`，详情显示「任务已更新，下一轮生效」；下次开工自动清除。
- **持久化**：`assignmentCheck` 与 `taskPending` 都写进 `team.json`，刷新/重启后还能看到告警。


## 内容质量门 v1（这一版新增）

- 只检查**交接元数据里声明过的**产物，未声明的草稿文件不拦。
- 确定性检查：`empty-artifact`（<32B）、`empty-code`（.py/.js/.mjs 等 <64B）、`bad-image`（PNG/JPEG/GIF/WebP 魔数不对）、`thin-data`（CSV/TSV 少于 2 行）、`thin-paper`（论文 .md/.tex <500B）、`missing-sections`（论文缺常见章节标题，告警）。
- 错误级：走守卫重试一次，仍不合格就 `blocked / low-quality-artifacts`；告警级：记审计/团队日志，成员详情显示「产物质量告警」。
- 不跑代码、不接评审模型；阈值是常量（32/64/500 字节），后续可按团队配置。


## 错误分类与瞬时重试（这一版新增）

- **分类**：`classifyError` 把 429/5xx、限流、超时、连接重置归为瞬时；401/403、模型不存在、400/422、取消归为永久。
- **退避重试**：瞬时错误最多重试 2 次（默认 5s、15s；`COMPETITION_RETRY_MS` 可调基值），期间成员状态为 `retrying`，面板显示「重试中」；重试 prompt 带 `【网络重试】`，不让成员以为是自己做错了。
- **永久/用尽**：直接 `failed`，错误码 `auth / model-missing / bad-request / cancelled / transient-exhausted`，详情里保留原始错误。
- **预算优先**：预算用尽时不做瞬时重试，直接失败。
- **宿主重载**：`retrying` 的成员在加载时转回 `pending`，由启动自愈接力，不会永远停在重试倒计时里。



## 上游失败传播（这一版新增）

- 成员永久失败（auth / model-missing / bad-request / transient-exhausted / stalled）时，所有仍在 `pending` 的传递下游会被标成 `blocked`，错误为 `upstream-failed:<失败角色>`，不再显示含糊的「等待」。
- 重跑或跳过失败成员后，`unblockDependents` 把只被它挡住的下游放回 `pending`；如果还有别的失败上游，继续保持 blocked。
- 团队状态会显示 `blocked`，审计记录一条 `blocked / unblock`；面板里 blocked 成员的详情会写「上游失败，等待重跑或跳过」。
- 浸泡测试从「12 队里 2 队直接卡在上游、1 队传递卡住」降到 **0 队上游卡住**，只剩预算暂停 1 队（预期）。

## 通知收件箱（这一版新增）

- **持久化**：提案、任务书、阻塞、停滞、失败、预算用尽都会写一条 `notifications`（最多 30 条），落 `team.json`，刷新/重启不丢。
- **未读**：快照带 `unread` 计数；频道条显示「通知 · N」，footer 也显示；点开是收件箱列表（时间、类型、正文），未读高亮。
- **已读**：收件箱里「全部已读」调 `readNotifications`，服务端写 `readAt`。
- **平台现状**：DSH 没有通用系统通知 API（只有账号通知的轮询插件），所以关掉页面时没有 OS 推送；收件箱负责「你回来时别错过」，浏览器通知负责「你在页面时提醒」。


## 工程拆分与 HTTP 测试（这一版新增）

- **模块拆分**：纯函数从 `index.js` 抽到 `lib/`——`handoff.mjs`（交接块、任务书解析、DAG 校验）、`errors.mjs`（错误分类）、`quality.mjs`（质量门）。`index.js` 只保留状态机与调度，测试仍从入口导入。
- **打包修正**：`package.json` 的 `files` 补上 `lib`、README、LICENSE；之前漏了 `lib`，别人按包安装会缺模块。
- **HTTP 路由测试**：用模拟 Host 捕获 `webServer` handler，覆盖同源校验、CSRF 头、坏 JSON、建队→查询、路径穿越、文件服务、models 映射、未知 action。
- **规模**：63 个用例；Client 仍是单文件，渲染层暂无自动化测试。

## HTTP 访问 token（这一版新增）

- 每次安装生成一个 32 位随机 token，存在 `$DSH_HOME/data/competition-team/http-token`，权限尽量设为 0600。
- 通过 `webserver/index-inject` 注入 `window.__COMPETITION_TEAM_TOKEN__`，只进入 DSH 页面；客户端在 `state / models / action` 请求里带 `x-competition-team-token`。
- 没有 token 的请求返回 403 `token`；跨域请求仍然先被同源检查拒绝。
- 产物 `file` 路由保留同源检查，不要求 token，因为 `<img>`/预览需要直接 URL；它仍限制在团队目录内。
- 测试覆盖：无 token 403、有 token 200、跨域仍 403。

## 边界

- 团队记录在 `<共享目录>/.dsh-competition/<团队 id>/`；索引在 `$DSH_HOME/data/competition-team/`。删团队只移出列表，不删会话和文件。
- 工作流只支持「前置依赖」这一种关系（DAG）；没有条件分支、循环、并行上限控制。
- 选到不可用的模型路由时，该成员这一轮会失败并显示原始错误，改模型后重跑即可。
- 自动接力依赖成员在两轮之间正常结束；模型反问你而停下时，节点显示完成，需要补一句指令。
- 成员共用一个工作目录，没有目录隔离。
